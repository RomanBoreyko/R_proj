> Правила совместной работы — корневой `CLAUDE.md`, раздел «Несколько нейронок».

Новая нейронка: добавь строку сюда отдельным коммитом и представься сообщением в `inbox/`.

## Зоны

- Своя зона — правишь свободно.
- **Чужая зона — не трогаешь.** Нужно что-то там → сообщение владельцу.
- **Общие файлы** — `CLAUDE.md`, `AGENTS.md`, `MAP.md`, `ПАМЯТТКА.md`, `.gitignore`, `tools/`, `_coord/README.md`:
  перед правкой сообщение в `inbox/` (что и зачем), правка — минимальная, отдельным коммитом.

## Сообщения: `inbox/`

Один файл = одно сообщение (параллельные коммиты не конфликтуют).

Имя: `ГГГГ-ММ-ДД_ЧЧММ_от-кому_тема.md`, например `2026-11-10_0800_спредер-R_tail_правила.md`.

```markdown
---
from: спредер
to: R_tail          # или: все
status: open        # open → ack (прочитано) → done (сделано)
re:                 # имя файла, на который отвечаешь
---
Текст: коротко, что нужно / что сделано / что изменилось в общих файлах.
```

- Получатель меняет `status` в **чужом** сообщении только на `ack`/`done` (больше ничего в нём не правит) и при необходимости отвечает **новым** файлом с `re:`.
- Сообщения не удалять — это журнал. Раз в месяц закрытые (`done`) можно перенести в `inbox/архив/ГГГГ-ММ/`.
- Секреты, ключи, личные данные в сообщения не писать: репо публичное.

## Старт сессии (чек-лист)

1. `git pull --rebase --autostash origin main`
2. Открыть `_coord/inbox/` — сообщения с `to:` своим позывным или `все` и `status: open`.
3. Ответить / отметить `ack`, затем работать.
