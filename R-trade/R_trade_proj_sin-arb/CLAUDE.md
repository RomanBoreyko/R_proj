## Что это

Торговая система Романа на **живом счёте Bybit UTA, режим Portfolio Margin**.
**С 16.11.2026 одно направление — оператор спреда SOXL/SOXS:**
- лонг-лонг перпов SOXLUSDT + SOXSUSDT в пропорции β;
- опционы SOXL как гамма-страховка;
- скальп колебаний перпами и коридор дельты.

Спецификация: `TRADING-SYSTEM/03-STRATEGIES/SPREAD-оператор-SOXL-SOXS.md`. Вход в доки: `TRADING-SYSTEM/00-INDEX.md`.

Прежние направления (D1 — арбитраж под прикрытием опционов, D2 — ETH perp+put, портфель корзин, рой ботов на шиткоинах) лежат в `TRADING-SYSTEM/99-АРХИВ/` до востребования. Как вернуть — `99-АРХИВ/README.md`.

Периферия: MetaScalp (исполнение), приложение TradingView (графики), MEXC.

## Правила (порядок важности)

1. **Только чтение API.** Ключ Bybit read-only, файл `C:\Users\DoOs\.bybit\credentials.json`.
   Никаких ордеров, переводов, настроек — сделки ставит пользователь сам.
   Разрешено: `/v5/market/*`, GET `/v5/account/*`, `/v5/asset/portfolio-margin`, `/v5/position/*`,
   `/v5/order/realtime`, `/v5/execution/*`, `/v5/earn/*`.
2. Ключи не печатать, не логировать, не коммитить, не класть в JSON-ответы и HTML.
3. **«Не фиксировать убытки»** — правило пользователя. Если вариант означает фиксацию убытка — прямо сказать, сколько фиксируется.
4. Цифры — только из API или файлов. Нет данных — «—». Не придумывать цены, IV, греки.
5. Персональных инвестсоветов не давать: анализ, сценарии, варианты; решает пользователь.
6. Пакеты не ставить без спроса; Python — stdlib (requests/pybit НЕ установлены).

### Правила риска
Действующие — `TRADING-SYSTEM/06-RISK/risk-rules.md`:
- IM ≤ 50%;
- Δ SOX в коридоре ±$40;
- тета книги не хуже −$10 в сутки;
- голые шорты запрещены;
- хедж другой монетой удваивает маржу (PM считает монеты отдельно).

## Дашборд — деск (главный рабочий инструмент)

- **Запуск:** `cd TRADING-SYSTEM/scripts/portfolio && python book_dashboard.py` → http://localhost:8899.
  - `/` — деск «спред SOXL/SOXS»;
  - `/old` — старая версия со всеми вкладками; их фоновые сэмплеры работают только с `--full`.
- **Что на деске:**
  - шапка (Счёт / SOX / Гамма / Плечи) обновляется раз в 2 с (`/desklive`);
  - блок «Гамма-скальп»: сетка коридора, учёт, β и шум хеджа, опционы у денег;
  - маржа спреда, дельта по конструкциям, ноги.
- **Переключатели в JS:** `DKETH=0` (ETH скрыт), `DKCHARTS=0` (графики спреда скрыты — Роман смотрит TradingView). Скрытый код не удалять.
- **Перед любой правкой прочитать `TRADING-SYSTEM/scripts/portfolio/DASHBOARD.md` целиком:**
  - инварианты §0;
  - ловушки фронтенда §5 (общий глобальный scope JS — проверять занятые имена grep'ом);
  - перезапуск §6 (HTML живёт в памяти процесса — убить процесс на 8899 и запустить заново);
  - историю — дописывать.
- `book_dashboard.py` правит и Gemini — перед правкой смотреть `_coord/CHAT.md` и время изменения файла.
- Остальные скрипты — таблица в `scripts/portfolio/README.md`.

## Как отвечать на «статус / анализ»

Свежие данные через API (read-only), коротко:
- эквити, IM/MM, запас до ликвидации;
- **Δ SOX** (SOXL-экв., с опционами и β), Γ книги, тета книги;
- безубыточный ход против RV;
- ближайшие экспирации SOXL, главные риски-сценарии (маржа Bybit: падение IV, гэп на открытии США).

Без «купи/продай» — варианты с цифрами и с учётом правила «не фиксировать убытки». После сделок пользователя сверять сторону и инструмент.
