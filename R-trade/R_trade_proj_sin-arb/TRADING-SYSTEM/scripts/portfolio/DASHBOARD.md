# Дашборд книги Bybit — техническая документация

Документ для разработчика или ИИ-агента, который будет дорабатывать дашборд. Читать целиком до первой правки.

Карта узлов в Obsidian: [[Дашборд]] (вкладки, модули, понятия, активы) · схема [[Дашборд.canvas]].

- **Запуск:** `python book_dashboard.py`, затем открыть http://localhost:8899
- **Зависимости:** только стандартная библиотека Python 3, без pip-пакетов.
- **Файлы:** `book_dashboard.py` (сервер, HTML и JS), `portfolio_book.py`, `tail_pairs.py`. Все три лежат в `TRADING-SYSTEM/scripts/portfolio/`.

---

## 0. Инварианты (нарушать нельзя)

1. **Только чтение.**
   - API-ключ Bybit read-only и лежит в `C:\Users\DoOs\.bybit\credentials.json`, вне волта.
   - Никаких ордеров, переводов и изменений настроек. Разрешены только эндпоинты `/v5/market/*` и GET-запросы `/v5/account/*`, `/v5/position/*`, `/v5/order/realtime`, `/v5/execution/*`, `/v5/earn/*`.
   - Торгует пользователь сам, вручную.
2. **Ключи не печатать, не логировать, не коммитить.** Не добавлять их в JSON-ответы, в HTML и в тексты ошибок.
3. **Не ставить пакеты без явного согласия пользователя.** Графики рисуются на `<canvas>` вручную, без библиотек.
4. **Цифры только из данных.** Если данных нет, показывать «—» или «нет данных», а не подставлять значения.
5. **Язык интерфейса — русский.** Пользователь торгует живым счётом Bybit UTA в режиме Portfolio Margin.

## 1. Архитектура

```
браузер ──fetch каждые 4–6с──> ThreadingHTTPServer (127.0.0.1:8899, book_dashboard.Handler)
                                 ├─ /        → HTML (одна строка HTML = r'''...''' внутри book_dashboard.py)
                                 ├─ /port    → portfolio_book.portfolio_snapshot(sget, pub, earn_snapshot)
                                 ├─ /gold    → book_dashboard.gold_snapshot()
                                 ├─ /tail    → tail_pairs.tail_snapshot(sget, pub)
                                 ├─ /pairs   → tail_pairs.pairs_snapshot(sget, pub)
                                 └─ /data    → book_dashboard.snapshot()   (LEGACY: старая «ETH книга», UI её больше не вызывает)
```

- Каждый маршрут отдаёт JSON. Любое исключение превращается в `{"err": "..."}` (обёртка try/except в `Handler.do_GET`), и фронт показывает ошибку в `#upd` или в строке статуса вкладки.
- **HTTP-хелперы** определены в `book_dashboard.py` и передаются в модули аргументами:
  - `sget(path, params)` — подписанный GET: HMAC-SHA256 по `ts+KEY+recv+querystring`, заголовки `X-BAPI-*`, recv_window 20000;
  - `pub(path, params)` — публичный GET.
- **Импорты.** Модули не импортируют `book_dashboard` и получают хелперы параметрами. `portfolio_book` импортирует утилиты из `tail_pairs`: `ff`, `_T`, `_bs`, `cached`.
- **HTML держится в памяти.** Python-код и HTML загружаются при старте, автоперезагрузки нет. **После любой правки сервер нужно перезапустить** (см. §6).

### Вкладки ↔ маршруты ↔ код

| Кнопка | id вкладки | Маршрут | Бэкенд | JS-рендер | Интервал |
|---|---|---|---|---|---|
| Портфель | `tabE` | `/port` | `portfolio_book.portfolio_snapshot` | `tick` → `renderPort` → `renderPVol`, `renderPSpot`, `renderPBS`, `drawPPay`, `renderPPos` | 4с |
| Золото XAUT/XAU | `tabG` | `/gold` | `gold_snapshot`, `gold_wings` | `gtick`, `renderGold`, `renderWings`, `drawSpread` | 4с |
| Хвосты ETH | `tabT` | `/tail` | `tail_pairs.tail_snapshot` | `ttick`, `drawDV` | 6с |
| Факторные спреды | `tabP` | `/pairs` | `tail_pairs.pairs_snapshot` (тяжёлая часть в фоне) | `ptick`, `drawZ` | 6с |

- Переключение вкладок — `showTab(t)`, где `t` ∈ `'E','G','T','P'`.
- Таймеры работают всегда, но каждый `*tick` сразу выходит, если активна не его вкладка. Исключение — `tick()` для `/port`: он опрашивает всегда, поэтому вкладка «Портфель» открывается мгновенно.

## 2. Модуль `portfolio_book.py` — вкладка «Портфель»

**Задача:** показать одни и те же блоки для всего портфеля и для каждой группы активов.

### Конфигурация (в начале файла)
- `GROUPS` — группа и её базовые активы:
  ```python
  {"ETH":["ETH"], "MNT":["MNT"], "SOL":["SOL"], "BTC":["BTC"], "QQQ":["QQQ"], "GOLD":["XAUT","XAU","XAG","GDX"]}
  ```
  - **Первый актив в списке — «главный»:** он задаёт ось payoff и датчик волы.
  - Всё, что не попало ни в одну группу, уходит в `OTHER` («Прочее»). Эта группа скрыта, если в ней нет позиций.
- `GNAME` — русские названия групп; `"ALL"` = «Весь портфель».
- `OPT_BASES` — активы с опционами на Bybit: ETH, MNT, SOL, BTC, QQQ, XAUT. Проверено через `tickers?category=option&baseCoin=X`.
- `FLAT_USD = 150` — порог |Δ$|, ниже которого позиция подсвечивается как нейтральная.
- `PAY_RANGE = (-0.45, 0.25, 140)` — диапазон шока для payoff и число точек.
- `RND` — точность округления сумм «куплено/продано».

### Данные за один вызов
- **Подписанные:**
  - `/v5/account/wallet-balance?accountType=UNIFIED` — эквити, IM, MM, свободные средства, баланс монет (`walletBalance`);
  - `/v5/position/list?category=option` — с пагинацией;
  - `/v5/position/list?category=linear&settleCoin=USDT|USDC`.
- **Earn:** `earn_fn()` (это `book_dashboard.earn_snapshot`, кэш 300с) → `pos` в формате `{coin: amount}`.
- **Публичные, через `cached`:**

  | Ключ кэша | Источник | TTL |
  |---|---|---|
  | `pb_lin` | все linear tickers | 5с |
  | `pb_opt_<BASE>` | option tickers по baseCoin | 10с |
  | `pb_rv_<BASE>` | дневные свечи `BASEUSDT` для RV30 | 600с |
  | `pb_vol_<BASE>` | итог датчика волы | 60с |

### Разбор символов
- **Опцион:** `BASE-DDMMMYY-STRIKE-C|P-USDT`, например `ETH-25DEC26-2000-P-USDT` или `MNT-25DEC26-0.46-C-USDT`. Страйк может быть дробным, поэтому всегда `ff()`, а не `int()`.
- **Перп:** `_perp_base(sym)` отрезает `USDT`/`USDC`/`PERP` от части до первого `-`: `ETHPERP` → ETH, `SAMSUNGEMUSDT` → SAMSUNGEM.
- **Группа** определяется по **точному** совпадению базы (`_grp`). Подстроку не использовать: старый `snapshot()` проверял `"ETH" in symbol` и ловил лишние символы.

### Единицы и формулы
- Греки берутся из `/position/list` как есть: **на позицию и со знаком** (у шорта знак отрицательный). Θ и Vega — в $ в день и в $ за 1 пункт волы. Δ и Γ — в единицах базового актива.
- `Δ$ = Δ · S`. Для опциона S = `underlyingPrice` из option tickers, для перпа — `markPrice`.
- **`Γ$ на 1% = Γ · S² · 0.01`** — на сколько $ изменится Δ$ при ходе актива на 1%. Только в этой единице гамму разных активов можно складывать, поэтому «Весь портфель» показывает её.
- **Истинная Δ актива** = Δ опционов + Δ перпов + спот (`walletBalance`) + Earn. «Нужный перп-хедж» = −истинная Δ.
- **Payoff по сетке шоков m из `PAY_RANGE`.** Каждый инструмент группы сдвигается на один и тот же % (`S·(1+m)`).
  - `pay` (на экспирации):
    - опцион: `side·sz·(intrinsic − entry)`;
    - перп: `side·sz·(S1 − entry)`;
    - спот и Earn: `q·S·m`, отсчёт от текущей цены, а не от цены входа.
  - `now` (T+0): Black-Scholes `_bs(S1, K, T, markIv, cp)` минус вход, IV не меняется.
  - Ось X: для группы — цена главного актива, для `ALL` — % (`pct: true`). В `ALL` двигаются вообще все активы на один %, корреляции не учитываются.
  - `be` и `be_now` — точки безубыточности: строгая смена знака между соседними точками.
- **Датчик волы `_vol(base)`:**
  - ATM IV = среднее markIv колла и пута на страйке, ближайшем к underlying, в ближайшей экспирации от 7 дней;
  - RV30 — дневные лог-доходности за 30 дней, годовой коэффициент считается по фактической плотности баров (у TradFi нет выходных);
  - сигнал по `ratio = IV/RV`: <0.9 дёшево, <1.1 норма, <1.3 повышенная, ≥1.3 дорого;
  - ранг — позиция IV в истории текущей сессии (`VOLH[base]`, теряется при перезапуске).

### β к ETH и стресс спреда (только вид `ALL`)
- `_betas(pub, bases)` — β и корреляция 4ч лог-доходностей базы к ETH за 30д (`kline interval=240 limit=180`, только соседние 4ч бары — у TradFi дыры), кэш 1800с. `BETA_REF="ETH"`.
- ETH-эквивалент позиции = Δ$·β. `eq_total` — по всем активам, `eq_crypto` — только базы из `tail_pairs.CRYPTO`.
- `_shock(inst, held, mv)` — P&L T+0 относительно текущего, если база b сдвинута на `mv(b)` (доля): перп линейно, опцион ΔBS при текущем markIv, спот/Earn `q·S·m`.
- Сценарии (`STRESS_MOVES` = ±5/10/20%): только ETH; только корзина (крипто-базы кроме ETH); ETH +m / корзина −m; согласованно по β (актив β·m). Некрипто-активы двигаются только в последнем.
- JSON: `groups.ALL.beta = {rows:[{base,dusd,beta,corr,crypto,eq}], eq_total, eq_crypto, basket:[..], stress:{moves:[..], rows:[{name,pnl:[..]}]}}`; `groups.ALL.tot.eq = eq_total`.
- Фронт: блок `#betawrap` (`betatiles`, `betatab`, `betastress`, `betanote`), рендер `renderPBeta(d,g)`, виден только при `PG=='ALL'`. Корреляция < 0.7 при |Δ$| ≥ `flat` подсвечивается «слабый хедж».

### Формат ответа `/port`
```jsonc
{ "t": "HH:MM:SS",
  "acct": {eq, im, mm, av, im_pct, mm_pct, buf},
  "stable": {"USDT": .., "USDC": ..},
  "order": ["ALL","ETH",...,"GOLD","OTHER"?],
  "flat": 150,
  "groups": { "<KEY>": {
      key, name, main, px, n, pct,
      rows: [{base, grp, px, spot, earn, od, og, ot, ov, pd, true, dusd, g1, hedge, up, active, n}],
      tot:  {dusd, g1, t, v, up, od_perp, true, g, hedge_xau?},
      B: {n,d,dusd,g,g1,t,v}, S: {...}, cov: {g,t,v},          // куплено / продано / покрытие %
      pay: [[x, pnl]], now: [[x, pnl]], be: [..], be_now: [..],
      pos: [{grp, sym, side, sz, d, dusd, g, t, v, up, iv}],
      vol: {base, iv, rv, prem, ratio, band, rank, lo, hi, exp, dte, K} | null,
      summ?: [...], vols?: [...]                              // только у "ALL"
  }}}
```

### Фронт
- Переключатель групп собирается в `#pgsel` из `order`. Выбор хранится в `localStorage` под ключом `pg`.
- Все группы приходят одним ответом, поэтому переключение не делает нового запроса.
- **Глобальные переменные JS вкладки:** `PORT` (последний ответ) и `PG` (выбранная группа). Не называть их `PD`: это имя уже занято вкладкой пар (см. §5).

## 3. Модуль `tail_pairs.py` — вкладки «Хвосты ETH» и «Факторные спреды»

### Общие утилиты
- `ff(x)` — безопасный float.
- `_exp_dt(code)` — дата экспирации; Bybit экспирирует в 08:00 UTC.
- `_T(code)` — время до экспирации в годах.
- `_N`, `_bs(S,K,T,σ,cp)` — Black-Scholes без ставки.
- `cached(key, ttl, fn)` — общий кэш модуля (`_C`).

### 3.1 `tail_snapshot` — продажа дальних путов ETH и вола
- **Конфиг `TAIL_CFG`:**
  - `far_pct` — порог «дальнего» пута, 0.85 от цены;
  - `maxloss_budget` — потолок суммарного макс. убытка спредов как доля эквити;
  - `mm_max` — не открывать новые продажи при MM выше этого;
  - `dvol_sell` / `dvol_cover` — перцентили DVOL для продажи и откупа веги;
  - `tp_capture` — тейк при сборе ≥ % премии;
  - `cand_dte`, `cand_delta`, `cand_width` — фильтры кандидатов в пут-спреды.
- **Источники:**
  - option tickers ETH (кэш 8с), ETHUSDT;
  - позиции и кошелёк;
  - DVOL ETH с Deribit `get_volatility_index_data` (`_dvol`, кэш 600с, перцентиль за год);
  - RV30 (`_rv30`).
- **Логика:**
  - дальние шорт-путы группируются по экспирам;
  - покрытие — купленными путами ниже в той же экспире;
  - максимальный убыток считается по payoff-сетке; `None` означает голый пут;
  - «крыло» — самый дешёвый пут на 50–600 ниже верхнего шорта, сами шорт-страйки исключены;
  - тактические хеджи — лонг-путы до 14 дней, стоимость в день = mark·q / max(dte, 0.25);
  - стресс — сетка ход×IV-шок: путы получают полный шок, коллы половину, при росте — треть;
  - кандидаты сортируются по доходу к риску в месяц.
- **Фронт:** элементы `tacct`, `twarn`, `tvbar`, `tvol`, `tdv` (canvas), `tgroups`, `thedge`, `tstress`, `tcand`.

### 3.2 `pairs_snapshot` — факторные пары без стопов
- **`PAIRS`** — список `(A, B, сессия, статус)`. Символы без `USDT`: код сам добавляет `USDT`, поэтому пары с `ETHPERP` и подобными не поддерживаются.
  - Сессии (`_sess`):
    - `ALL` — крипта 24/7;
    - `US` — RTH 13:30–20:00 UTC летом / 14:30–21:00 зимой, DST-окна захардкожены на 2026–2027;
    - `KR` — 00:00–06:30 UTC в будни;
    - `WK` — будни круглосуточно.
  - Статус `рабочая` даёт торговые сигналы. `наблюдать` → в колонке сигнала пишется «без стопа не торговать».
  - Сейчас добавлены ETH/BTC, ETH/SOL (рабочие), ETH/ETHFI, ETH/LDO, BMNR/ETH, ETH/MSTR (наблюдать), а также TradFi-пары.
- **`PAIR_CFG`:**
  - `W=260` — окно в 30-минутных барах внутри сессии;
  - `zin=2` — вход, `zadd=3` — добор, выход при z=0;
  - `tmax_d=10` — выход по времени;
  - `budget=30` — бюджет на пару в $;
  - `days=80` — глубина истории.
- **`CRYPTO` и `_fee(sym)`:** мейкер 0.036% для крипто-перпов, 0% для TradFi (ставки пользователя проверены через `/v5/account/fee-rate`). Через них считаются `bt.cost` (круг мейкером обеих ног в бп ноги A) и `bt.net = avg − cost`.
- **Математика:**
  - `_roll` — скользящая OLS `ln A ~ ln B` за O(n) на префиксных суммах; даёт β, среднее, σ остатка и z;
  - `_bt` — бэктест без стопа, PnL в бп ноги A; MAE — худшая просадка внутри сделки; `open` — позиция, которую модель держит на последнем баре.
  - Размер ног: нога A = `budget / (2·|MAE|)`, нога B = β·A, количества округляются по `qtyStep` из `instruments-info`.
- **Тяжёлая часть `_pairs_heavy`** (свечи всех символов, бэктесты, бета к QQQ) занимает 30–60с. Она идёт **в фоновом потоке** (`threading`, `_PL`/`_PS`), результат кэшируется на 30 минут. Пока расчёта нет, ответ — `{"loading": true}`. Live-z считается по mid стакана из linear tickers (кэш 4с).
- **`FACTORS`** — фактор: `({символ: вес}, лимит $)`. Таблица корзины берёт **только USDT-перпы** и исключает ETHUSDT: его дельта — хедж опционов, иначе картина искажается.
- **Фронт:** `pbar`, `ptab` (клик по строке выставляет `PSEL` и рисует z в `pcv`), `pnote`, `pfac`. Последний ответ лежит в глобальной `PD`.

## 5. Фронтенд: соглашения и ловушки

- **Весь HTML, CSS и JS** — одна Python raw-строка `HTML = r'''...'''`. Внутри нельзя писать `'''`. JS-шаблоны `${...}` использовать можно: строка не форматируется Python.
- **Все `<script>` делят одну глобальную область видимости.** Повторное объявление `let` или `const` роняет **весь** скрипт: кнопки перестают работать, в консоли `Identifier 'X' has already been declared`. Это уже случалось с `PD` и `sg`.
  - Занятые глобальные имена: `$`, `tile`, `sg`, `TAB`, `renderPBeta`, `LAST`, `GREEK`, `GL`, `PORT`, `PG`, `PSEL`, `PD`, `GW`, `GLD`, `cl`, `vcls`.
  - Перед добавлением имени проверить его так: `grep -nE "(const|let|function) ИМЯ\b" book_dashboard.py`.
  - Новый код вкладки лучше давать с префиксом (`port*`, `tail*`, `pair*`).
- **Хелперы:**
  - `$(id)` — getElementById;
  - `tile(label, value, cls)` — плитка;
  - `sg(v)` — знак «+» у числа;
  - CSS-классы: `pos` (зелёный), `neg` (красный), `warn` (жёлтый), `gbtn` и `gbtn.on` (кнопки и переключатели), `row` и `tile`.
- **Тема только тёмная** (фон `#0d1117`).
- **Canvas рисуется вручную** (`drawPPay`, `drawSpread`, `drawDV`, `drawZ`): оси, подписи и легенда — функциями 2D-контекста.
- **localStorage:**
  - `tab` — восстанавливаются только G, T и P; по умолчанию открывается E;
  - `pg` — группа портфеля;
  - `gw` — окно золота.

  Каждый доступ обёрнут в try/catch.

## 6. Запуск, перезапуск, проверка

## 7. Известные ограничения и техдолг

- `datetime.utcnow()` устарел и даёт DeprecationWarning (`dte_of`, `vol_snapshot`, `_T`). Заменить на `datetime.now(timezone.utc)` с учётом aware и naive дат.
- **Legacy `/data` и функция `snapshot()`** ещё содержат ETH-специфику и проверку `"ETH" in symbol`. При удалении убрать маршрут, функции и неиспользуемые JS-функции (`betaTS` и др.) вместе.
- **Payoff приближённый:**
  - экспиры смешаны, кривая «на экспирации» = внутренняя стоимость каждой ноги;
  - T+0 — BS с текущим markIv без улыбки и без изменения IV;
  - в `ALL` шок однородный.
- **В стрессе нет пересчёта маржи** (ни Portfolio Margin, ни IM/MM после шока).
- **Ранг волы** (`VOLH`) и история беты (`HIST`) живут только в памяти и сбрасываются при перезапуске.
- **Пары:**
  - бэктест на 80 днях; у US-пар 2–6 сделок, это не статистика;
  - «модель в позиции» — состояние бэктеста, а не сделка пользователя;
  - время входа пользователя в пару нигде не хранится;
  - для пар с маленьким MAE (BMNR/ETH) размер ног раздувается;
  - DST-окна `_sess` захардкожены до 2027 года.
- **Портфель:** USDT и USDC считаются стейблами с Δ=0. Отрицательный баланс USDT (заём) виден только в строке-сводке, отдельной плитки «плечо» пока нет.
- **Сеть:** таймауты urllib 15–30с. При недоступности Bybit маршрут отдаёт `err`, а UI показывает его в строке статуса.
