> Составлена 08.10.2026 после разгребания. Читать вместе с `MAP.md`
> (карта — ЧТО где лежит; эта памятка — КАК с этим работать).

## Золотые правила (3 штуки)

1. **Один волт — один репозиторий.** Все коммиты и пуши делаются из корня
   `D:\Vault\Project\R_projekt`. Никаких `.git` внутри подпапок — это было
   корнем всех бед (циклический remote, перезапись main).
2. **Git — для версий, Syncthing — для доставки.** Syncthing развозит файлы
   на смарт/планшет, но не помнит историю. Всё, что жалко потерять, должно
   быть закоммичено и запушено на GitHub.
3. **Пушим с ноута сразу после осмысленного изменения.** Не «раз в месяц кучей»,
   а маленькими коммитами с понятным сообщением. Два дня работы без пуша —
   уже риск.

## Порядок действий на ноуте

```bash
cd D:\Vault\Project\R_projekt
git status                    # что изменилось
git add -A && git commit -m "понятное сообщение"
git push origin main          # remote уже HTTPS — работает из этой сети
```

Если работа велась в `R_tail.0.4/` (сабмодуль) — сначала коммит и пуш
**внутри сабмодуля**, потом в корне волта (указатель сабмодуля обновится).

## Чего НЕ делать

- Не создавать новые git-репозитории внутри волта.
- Не коммитить: `desktop.ini`, `.obsidian/workspace*.json`, `node_modules`,
  `TRADING_BOOK.xlsx`, `ChatExport_*`, секреты/API-ключи (всё это уже в `.gitignore` — не вытаскивать оттуда).
- Не работать одновременно с двух машин над одним файлом без пуша между ними —
  Syncthing размножит конфликтные копии.
- Не экспортировать телегу прямо в корень Vault без паузы Syncthing.
- Не переименовывать/не двигать папки проектов «вдруг» — каждое перемещение
  через `git mv`, чтобы история сохранилась.

## Чек-ап раз в месяц (5 минут)

1. `git status` в волте и в `R_tail.0.4/` — пусто?
2. `git log --oneline -3` + push — всё уехало на GitHub?
3. Syncthing: нет ли конфликтных копий (`*sync-conflict*`)?
4. MAP.md: не завёлся ли новый «хлам» в корне?
